# 03 — Why ChainBridge, why now.

### Competitive landscape

Each player owns one piece. None compose the whole stack. None are positioned to.

| Player | Owns | Missing |
|---|---|---|
| **Coinbase** | x402 payment rail | No agent identity or reputation layer |
| **Anthropic** | MCP protocol | Pure off-chain, no payments or identity |
| **Google** | A2A protocol | No chain integration |
| **Ethereum Foundation** | ERC-8004 spec | Just the spec, no SDK |
| **Olas (Autonolas)** | Full agent framework | Opinionated, locks you in |
| **thirdweb Engine** | Agent wallets | Wallet-focused, not standards-composing |
| **Virtuals, Fetch.ai** | Agent marketplaces | Closed ecosystems, not infrastructure |

> ✓ **The wedge in one sentence**
>
> ChainBridge is the standard library for autonomous agents on Ethereum. Identity, payments, reputation, and orchestration — composable, audited, MIT-licensed.
>
> It is to agents what Vercel's AI SDK is to LLMs: an unopinionated bridge that ships *with* the dominant frameworks rather than competing with them.

### Defensibility — why this compounds

| Moat | Why it compounds |
|---|---|
| **Settlement volume** | Once payment flow runs through ChainBridge Settlement, switching cost is real. Stripe-shaped lock-in. |
| **Audited security primitives** | Every prevented exploit is a story. Trust accrues. Hard to replicate. |
| **Standards body relationships** | Be the reference SDK that ERC authors point to. Marketing flywheel. |
| **Open-source contributor network** | Niche adapters shipped by community. Each is a customer-facing case study. |
| **Insurance pool history** | Insured volume with zero claims is unrepeatable by a new entrant. |
